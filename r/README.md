# stanli for R

Compile and sample Stan models without a C++ toolchain.

## Install

```r
# prebuilt binaries from R-universe (recommended)
install.packages("stanli", repos = "https://seantalts.r-universe.dev")

# or from source
# install.packages("remotes")
# remotes::install_github("seantalts/stanli", subdir = "r")

# or from a checkout
# R CMD INSTALL r
```

A source install builds a 40 KB C bridge with the toolchain R already expects
for source packages (Xcode command line tools on macOS, `r-base-dev` on Debian
and Ubuntu, Rtools on Windows). The sampler is not compiled here.

Then, once per machine:

```r
stanli_install()
```

This downloads the runtime for your platform, about 9 to 12 MB, into
`tools::R_user_dir("stanli", "cache")`, pinned to the release the package was
built against. After a package upgrade the old runtime is not found and this
step runs again. Nothing is fetched without it. Set `STANLI_RUNTIME` to use a
library you built yourself.

## Use

```r
library(stanli)

m <- stanli_model(file = "eight_schools.stan", data = list(J = 8L, y = y, sigma = s))
fit <- sample_model(m, chains = 4, seed = 1)

summary(fit)          # mean, MCSE, sd, quantiles, bulk/tail ESS, R-hat
stanli_diagnose(fit)  # divergences, treedepth, E-BFMI, R-hat, ESS
as_draws_array(fit)   # a posterior::draws_array
```

`code =` takes the model source directly. `#include` directives search the
directory containing `file`; add shared directories with
`include_paths = c("shared", "vendor/stan")`, searched in order before the
file's directory. A model keeps its compiled includes, so later sampling does
not reread them.

Sampling prints per-chain progress, elapsed times, and any divergence or
maximum-treedepth warnings; `refresh = 0` silences it. Per-chain times and
problem counts are in `fit$report`. Chains run in parallel by default, each
with its own executor and RNG stream, so a parallel run is byte-identical to a
sequential one.

`summary()` uses Stan's own estimators (rank-normalized split R-hat, bulk and
tail ESS, MCSE), so it agrees with `stansummary`. `stanli_diagnose()` runs the
checks a Bayesian workflow turns on, including E-BFMI. `optimize_model()`
finds the posterior mode by L-BFGS; its `$unconstrained` element is what
`sample_model(init = )` takes, and `unconstrain(m, list(mu = 0.5, sigma = 1.2))`
builds the same vector from constrained starting values, naming a parameter
that is missing, the wrong size, or outside its support.
`pathfinder_init = list()` initializes NUTS from single-path Pathfinder
(overrides: `num_iterations`, `num_elbo_draws`, `history_size`,
`init_radius`); it excludes explicit `init` and does not resample.

## Workflow packages

`bayesplot`, `loo`, `tidybayes` and `posterior` are optional and work on a fit
directly: `bayesplot::nuts_params(fit)`, `bayesplot::log_posterior(fit)`,
`bayesplot::rhat(fit)`, `bayesplot::neff_ratio(fit)`,
`tidybayes::spread_draws(fit, mu, theta[j])`, and `loo::loo(fit)` when the
model declares pointwise `log_lik` in generated quantities. `neff_ratio()`
uses bulk ESS where bayesplot's CmdStanMCMC method uses basic ESS. For
cmdstanr's default summary table use
`posterior::summarise_draws(as_draws_array(fit))`; `summary(fit)` keeps the
stansummary table. Saved warmup is excluded from `as_draws_array()` and the
ecosystem methods unless `inc_warmup = TRUE`.

[Coming from cmdstanr](../docs/from-cmdstanr.md) translates the API call by
call. [Teaching with stanli](../docs/teaching.md) covers classroom
installation, offline labs, and models generated by brms and Rethinking.

## Fit adapters

Three views of a fit serve code written against RStan or CmdStanR:

| adapter | returns | needs | limit |
| --- | --- | --- | --- |
| `as_stanfit(fit)` | an S4 subclass of `rstan::stanfit` with live density, gradient and transform methods | RStan, loaded on conversion only | passes `inherits(x, "stanfit")`; exact class-equality checks and RStan's native resampling do not work |
| `as_rfit(fit)` | an S3 object with RStan-style `extract()`, `summary()$summary`, `get_sampler_params()` and `get_elapsed_time()` | stanli and optional posterior | `n_eff` and `se_mean` use posterior's basic ESS and need not match RStan's |
| `as_cstanfit(fit)`, `sample_cstan()`, `cstan_model(code)$sample()` | an object with CmdStanR-style `$draws()`, `$summary()`, `$sampler_diagnostics()`, `$metadata()`, `$time()` and `$loo()` | stanli and optional posterior and loo | its own `stanli_cstanfit` class; no CSV or executable methods, no LOO moment matching |

<a id="native-rstan-fits"></a>
`as_stanfit()` builds the object in memory from stored arrays and retains the
model for `rstan::log_prob()`, `grad_log_prob()`, `constrain_pars()` and
`unconstrain_pars()`. Density methods always include the parameter-transform
Jacobian: `adjust_transform = FALSE` errors, and so does a `STANLI_LITE_LP`
runtime, whose `lp__` differs by a constant. Extraction, summaries, plotting,
ordinary LOO, ShinyStan, and `loo::loo_moment_match(sf, loo = loo::loo(sf), cores = 1)`
work. RStan binaries are on CRAN for supported macOS and Windows R versions;
install with `type = "binary"` to avoid a C++ toolchain. Load RStan before
rethinking in a fresh session, or rethinking's placeholder `stanfit` class gets
in the way.

`saveRDS()` keeps the draws but not the live model pointer. After `readRDS()`,
recreate the model from the same source and data and reattach it:

```r
saved <- readRDS("fit.rds")
m <- stanli_model(file = "model.stan", data = original_data)
sf <- as_stanfit(saved, model = m)
```

Without a model, extraction and summaries still work and density calls give an
attachment hint. Set R's seed before conversion for reproducible permuted
extraction.

<a id="native-r-style-fit-methods-without-rstan"></a>
`as_rfit()` never loads RStan. The result keeps class `stanli_fit`, so the
bayesplot, loo and tidybayes methods still apply. Consumers that call
`rstan::extract()` must call `stanli::extract()` for it instead.

<a id="cmdstanr-style-fit-methods"></a>
`sample_cstan()` takes CmdStanR-style sampler arguments and returns
`as_cstanfit()`; unknown options fail. `cstan_model(code)$sample(...)` accepts
the same arguments, so a CmdStanR sampling call can be reused by changing the
constructor. Initial values are complete constrained lists, one per chain, or a
function returning a list.

```r
fit <- sample_cstan(
  model_code = "parameters { real mu; } model { mu ~ normal(0, 1); }",
  chains = 4, parallel_chains = 4, iter_warmup = 500, iter_sampling = 1000,
  init = list(mu = 0), seed = 42, refresh = 0
)
fit$draws("mu")
fit$summary("mu", "mean", "sd", "rhat", "ess_bulk")
```

Summaries use posterior's rank-normalized R-hat and bulk/tail ESS, matching
CmdStanR. `$metadata()` iteration counts are before thinning. Diagnostic
columns are in alphabetical order, so select them by name. `$stanli_fit()`
returns the original fit.

## Runtime and compiler

The runtime is a separate shared library of about 29 MB holding stan-math,
the density kernels and the interpreter, so installing the R bridge never
compiles it. Package and runtime are versioned separately, so the C ABI
carries a layout version (`stanli_abi_version()`) and loading refuses a
mismatch with a message saying which side to update. The macOS and Linux
runtimes embed the Stan compiler. On a runtime without one, R uses
`STANLI_STANC` if set, then `stanli-compile` beside the runtime, then stock
`stanc` beside the runtime or on `PATH`, then the bundled JavaScript compiler
through V8; on Windows the compilers are short-lived subprocesses.

## Within-chain parallelism

`threads_per_chain = 4` in `sample_model()`, `sample_cstan()` or
`cstan_model(code)$sample()` runs eligible `reduce_sum` calls on persistent
worker teams. [Native reductions](../docs/native-reduce-sum.md) covers
eligibility, memory behavior, and the `fit$model$reduce_sum_count` and
`fit$model$reduce_sum_fallbacks` diagnostics.

## Not here yet

`optimize_model()` returns the posterior mode. CmdStan's `optimize` defaults
to `jacobian=0`, the penalized maximum likelihood, which stanli cannot offer:
the change-of-variables Jacobian is folded into the graph when the model is
lowered.
