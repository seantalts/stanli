# Issue #656: structural reproduction search, round 2

## Evaluator before screening

The first round tested one synthetic covariance construction and did not
reproduce the social report. This round systematically varies the program
structure and matrix geometry without relying on the unavailable original
model. No source fingerprint, model name or fixture-specific runtime path
is permitted.

Baseline remains fetched main
`0eb880b9b9579cd28ca64c3afa4257cba9adca1e`; this worktree's ancestry was
verified before screening. The baseline runtime and independent oracle
provenance are the same as [round 1](2026-11-23-issue-656-investigation.md).

Two explanations are tested separately:

1. **Structural lowering or shape/output-path failure.** Prediction: a
   valid construction fails compilation, preparation, gradients or
   `write_array` for a particular representation or shape boundary,
   regardless of ordinary matrix conditioning. Screen user-function returns,
   symmetric indexed writes, block/row slices, arrays of matrices,
   parameter/data branches and transformed-data/transformed-parameter/
   generated-quantity placement independently.
2. **Numerical conditioning or domain behavior.** Prediction: failure or
   numerical disagreement follows diagonal jitter/parameter values across
   several representations, while ordinary well-conditioned controls work.
   Compare jitter 0.1, 1e-8 and 1e-14, keep legitimate rejections, and check
   suspect cases with independent CmdStan rather than widening a tolerance.

The runtime-only screen uses N=0, 1, 2, 35, 36 and 64, three fixed parameter
points, and deterministic data/permutations. It records compilation and
preparation separately, gradient status and exact error, output status,
non-finite counts and checksums, and peak RSS. N=35/36 straddles the
Cholesky reverse-kernel implementation boundary. N=0 is tested rather than
presumed invalid.

Each program/data case runs in its own subprocess, with a 30-second wall
timeout, 20-second CPU limit, no core dumps and a parent RSS guard at
512 MiB. macOS rejected setting RLIMIT_DATA even on the one-element smoke
probe, so RSS is explicitly monitored by the parent instead. That harness
setup error occurred before loading the runtime and is not a model failure.

The semantic oracle checks log density, every gradient component, and all
write-array values, names/order and non-finite classes against an
independently compiled CmdStan model. Runtime-only finite output is merely a
screening result, not correctness evidence. Large ULP differences in a
poorly conditioned case must be measured and explained; a scaled-error
summary is not a ten-ULP proof.

## Structural-screen result

The [initial runtime screen](data/2026-11-23-issue-656-round2-screen.json.gz)
completed. Thirteen valid construction/placement
forms across six shapes and three jitters (234 program/data cases, 702
gradient and output evaluations each) completed without a crash, low-level
error, rejection or non-finite output. Three additional branch forms need a
generator correction: the first generated program used
`tcrossprod(vector)`, which is invalid Stan. This compiler type error is a
probe bug and is not counted as a Stanli defect. The corrected program uses
an outer product.

User-function, inline scalar, matrix-array, user-function-array and nested
factor-call forms were bitwise equal in the runtime screen. Row-vector,
permuted-write and nested-local forms differed by roughly 1e-15 on ordinary
jitter. At jitter 1e-14, their maximum absolute density/gradient differences
from the UDF form were respectively 3.29e-4, 2.55e-4 and 1.62e-3 (all at
N=64, point 0). These compare different source representations within
Stanli and initially did not establish any disagreement with CmdStan.
The exact-source checks below classify one of those pairs. Maximum observed
worker RSS in the initial screen was 68 MiB.

The [corrected branch screen](data/2026-11-23-issue-656-round2-branches.json.gz)
completed 72 further program/data cases: data-dependent branches at both
selector values, parameter-dependent branches across all three parameter
points, and parameter-dependent generated-quantity branches. Compilation,
preparation, gradients and outputs succeed throughout. Together these
cover **306 valid program/data cases and 918 fixed-point gradient/output
evaluations**, across sixteen construction/placement forms. The 72 initial
invalid-Stan generator cases are preserved in the initial raw record but
excluded from this valid-case count. No timeout, signal, RSS-guard kill or
low-level bit-length error occurred.

## Independent numerical checks

The [oracle harness](../../harnesses/diagnostics/covariance_oracle_probe.py)
compiled the exact generated source with pinned independent CmdStan for
three representative forms: permuted indexed writes in transformed
parameters, matrix-array construction in generated quantities, and
Cholesky decomposition in transformed data. Each was checked at N=0, 1,
35, 36 and 64, at all three jitters and three parameter points:
**45 program/data cases, 135 fixed-point comparisons**.

[Raw oracle evidence](data/2026-11-23-issue-656-round2-oracle.json.gz) records
the build commands and hashes. All three reference builds produced no
compiler diagnostics. Log density and every gradient component agree
within **1 ULP**. Every deterministic write-array value agrees within
**4 ULP**, with exactly matching output names and column order. No
non-finite-class disagreement or one-sided rejection occurred, including
the zero-size and jitter-1e-14 cases.

An [additional exact-source UDF oracle](data/2026-11-23-issue-656-round2-udf-oracle.json.gz)
checked N=35/36/64 at jitter 0.1 and 1e-14: six program/data cases and
eighteen points, with the same 1-ULP density/gradient and 4-ULP output
maxima and exact names/order. Its reference build also emitted no compiler
diagnostics. Across both oracle batches, this is **51 program/data cases
and 153 fixed-point comparisons**.

The [paired independent CmdStan values](data/2026-11-23-issue-656-round2-cross-source.json.gz)
for UDF and permuted-write sources exhibit the same cross-source
ill-conditioned difference: maximum absolute density/gradient difference
2.5485076791520456e-4 at N=64, jitter 1e-14, point 0. Each exact source
separately agrees with Stanli within 1 ULP, so this pair's source-dependent
numerical behavior is not a Stanli-only discrepancy. This does not prove
the mathematical answer accurate to ten ULP in an ill-conditioned problem.

These are representative exact-source oracle checks, not a verification of
every structural-screen form. The row-vector and nested-local forms still
require their own exact-source oracle checks before assigning their larger
differences a cause or declaring them correct.

## Bounded scale and memory probe

The [larger UDF screen](data/2026-11-23-issue-656-round2-scale.json.gz) adds
N=128 and 256 at jitter 0.1 and 1e-8, with the same subprocess guards and
three points. All four cases complete compilation, preparation, gradients
and output evaluation. Peak RSS reaches about 372 MiB at N=256.

A [separate memory-attribution probe](data/2026-11-23-issue-656-round2-memory.json.gz)
compares the indexed user function with a mathematically equivalent
builtin covariance construction at jitter 0.1:

```stan
add_diag(gp_exp_quad_cov(to_array_1d(x), sqrt(amplitude),
                         inv_sqrt(2 * rate)), jitter)
```

This represents the same mathematical covariance
`amplitude * exp(-rate * square(x[i] - x[j])) + jitter * I`. Square roots,
inverses, kernel arithmetic and reverse accumulation make these different
floating-point programs; algebraic equivalence does not assert bitwise or
ten-ULP numerical equivalence. The identical N=256 deterministic data and
standalone sources are retained as
[data](../../harnesses/diagnostics/fixtures/covariance_n256.json),
[indexed UDF](../../harnesses/diagnostics/fixtures/covariance_udf.stan), and
[builtin form](../../harnesses/diagnostics/fixtures/covariance_builtin_equivalent.stan).
The checked-in standalone source copies trim trailing whitespace; raw
records retain the original generated-source hashes and the generator
remains the source of the measured programs.

These are **single-run diagnostic timings and process high-water marks**,
not a performance improvement claim, steady-state retained-memory
measurement or controlled baseline/candidate benchmark. High-water marks
are inclusive, not additive or precise live-allocation attribution.
Compilation's baseline is about 26 MiB; most of the observed UDF growth
appears during preparation and evaluation, rather than source compilation.
The stable C ABI exposes no aggregate prepared op/slot counts; a separate
instrumented graph/execution report is needed for that attribution.

The native UDF/builtin comparisons at these stress sizes are also not
bitwise: over N=128/256 and all three points the largest absolute
density/gradient difference is 6.54e-13 and the largest scaled error is
2.14e-14. Differences near zero reach **13,568 ULP**. No tolerance was
widened, and no exact-source CmdStan oracle at these stress sizes or
write-array value equivalence between the two formulations was established
in this memory experiment.

N=512 was deliberately not attempted. N=256's measured 374-MiB peak is
already near the 512-MiB guard; larger dense storage could exceed it.
Killing a process with an imposed limit would not reproduce the user's
error. The bounded observation instead supplies a resource-scaling lead:
custom element-by-element construction can consume substantially more
preparation/evaluation memory than a builtin covariance kernel, even when
every phase succeeds. CmdStan's memory cost for the same large programs
and the exact graph/tape/storage owner remain unmeasured.

Separately, the R sampler allocates all output columns across all chains
and stored draws (`r/src/bridge.c`, `stanli_r_sample`), then constructs the
draw array in `r/R/stanli.R`. The public rethinking Experimental integration
passes `use_pars` to RStan but does not pass an output-variable selection
to Stanli. Large covariance matrices declared in transformed parameters
can therefore add a large retained-output cost. For this synthetic model,
N=256 has 258 unconstrained parameters but 131,587 output columns. This is
a source-level resource hypothesis, not an observed allocation failure;
the probe deliberately did not allocate thousands of such draw rows.

The current generator uses the corrected valid branch programs and adds
the builtin-equivalent variant used in the memory probe. The initial
screen's invalid branch programs are historical generator mistakes, not
expected failures of the current harness.

No production changes have been made, and the social report remains
unreproduced. The strongest next experiment is memory attribution and a
matched CmdStan resource comparison on the retained large UDF program,
followed by a generic fix only if that identifies avoidable work. This
round does not establish sampling/posterior parity for the structural
grid, a general ten-ULP bound, or the cause of the original low-level error.
