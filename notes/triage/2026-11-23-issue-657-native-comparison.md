# Issue #657: native gradients and a standard synthetic fit

**The synthetic searches did not reproduce a current 500-subject slowdown on
this machine.** This is useful negative evidence about the tested structures,
not a contradiction of the public report or grounds to close
[#657](https://github.com/seantalts/stanli/issues/657). Unlike the
[first diagnostic](2026-11-23-issue-657-investigation.md), this round measures
both gradients in native C++ loops using the same timer and point protocol.
It also compares one standard four-chain fit with matched model, data and
sampler settings. There is no production optimization or runtime change.

## Identities and evaluator

Base remains fetched `origin/HEAD`
`0eb880b9b9579cd28ca64c3afa4257cba9adca1e`; its ancestry was checked before
continuing. The runtime is the official dev build
`abi6-0eb880b9b957-Darwin-arm64-threads`, with source R wrapper 0.30.1 built
privately from that base. CmdStan 2.40.0 and stock stanc are the pinned
independent oracle. Host: Apple M3 Ultra, macOS arm64, R 4.6.1, brms 2.23.0.
Shared dependencies were read only; reference executables were built into
this issue worktree's `.cache/issue657/screen`.

The [generator](../../harnesses/issue657_mixed_model.R) produces ordinary
random-intercept/random-slope workloads with deterministic data and proper
priors. The bounded matrix was:

- Gaussian, correlated noncentered effects, generated by brms.
- Bernoulli-logit, correlated noncentered effects, generated by brms.
- Gaussian, centered uncorrelated effects, a separate canonical Stan program.
- Right-censored Gaussian, correlated noncentered effects, generated by brms.
  This adds a legitimate per-observation data-dependent likelihood branch;
  it does not add artificial busywork.

The first three used J = 10 with five observations per subject, and J = 500
with five or 100 observations per subject. Censoring used J = 10 and 500,
20 observations per subject. Different workloads deliberately have different
geometry; **each backend comparison uses identical source and data**.

Two explanations were kept distinct: gradient/working-set costs could grow
with model size, while different NUTS trajectories could request more work.
Output materialization was a third candidate because brms retains many
transformed random-effect columns. Measurements below retain gradient work,
leapfrogs, output size and separate interface phases rather than attributing
the public report to a kernel from total wall time alone.

## Matched native gradient screen

[The native driver](../../harnesses/issue657_native_grad.cpp) calls the current
C ABI in a C++ loop. The independent generated-model driver is the existing
`tools/bench_cmdstan_grad.cpp`. Both use `tools/benchmark_timer.hpp`, identical
unconstrained points, 20 ms warmup and 40 ms measurement windows per point.
Builds use `-O3 -ffp-contract=off`; the reference source is compiled with
stock stanc `--O1`, and Stanli uses its shipped embedded compiler and default
policy. Three alternating paired rounds follow one discarded warmup pair;
the displayed spread is the range over paired rounds and points, not a
confidence interval. Compiles and other agents' native work were paused
during timing. Model construction used `allow_interpreter=FALSE` throughout.

## Full NUTS comparison

Initial 300-warmup/300-draw, two-chain screens of the three uncensored
500-subject/five-observation workloads were faster in Stanli, but every
backend's maximum R-hat exceeded 1.03 and minimum bulk ESS was below 200.
Those raw outcomes are retained as **unconverged screens**, not inferential
performance conclusions. Rather than expanding a grid to hunt for a slow
sign, one Gaussian noncentered case advanced to a standard fit.

[The fit harness](../../harnesses/issue657_fit.R) uses the same program/data,
seed 657, zero unconstrained starts, diagonal metric, target acceptance 0.8,
maximum depth 10, four **serial** chains, 1,000 warmup and 1,000 retained
draws per chain. Warmup is saved to retain all leapfrog diagnostics. CmdStan
CSV uses 17 significant digits. Both fits have 1,006 unconstrained parameters
and the same model-column schema/counts: 3,015 analysis columns after dropping
`lprior` and `lp__`. This does not mean identical draws or identical output
costs. CmdStan writes CSV; Stanli returns in-memory arrays.

| Quantity | Stanli | CmdStan |
| --- | ---: | ---: |
| R sample-call wall time | 7.217 s | 35.851 s |
| Engine reports, warmup + sampling over serial chains | 6.956 s | 29.288 s |
| Subsequent array extraction / CSV read | 0.061 s | 3.858 s |
| Total leapfrogs, including warmup | 255,196 | 242,409 |
| Post-warmup leapfrogs | 76,032 | 62,128 |
| Post-warmup divergences / depth-limit hits | 0 / 0 | 0 / 0 |
| Maximum R-hat over analysis columns | 1.00727 | 1.00721 |
| Minimum bulk ESS over analysis columns | 755.55 | 901.10 |
| CSV bytes | 0 | 494,768,065 |
| Retained post-warmup analysis array bytes | 96,762,984 | 96,762,608 |
| Whole R-process peak RSS, bytes | 1,432,354,816 | 1,074,577,408 |
| Whole R-process peak memory footprint, bytes | 1,407,633,016 | 930,302,640 |

The sample-call comparison includes different materialization paths and R
interface work; it is **not isolated sampler/kernel time**. Engine reports
also include their output work. Source compilation was completed separately
before sampling. Whole-process memory includes subsequent extraction,
posterior summaries and retained results, so it cannot be attributed to
runtime-only peak memory. The higher Stanli RSS is a distinct measurement
lead; it should not be hidden by faster elapsed time or described as a proven
runtime allocation defect.

Both fits pass the stated R-hat/ESS/diagnostic screen on this single seed.
Among 3,012 nonconstant columns with finite MCSEs, the largest posterior-mean
difference is 3.463 combined MCSEs (`z_1[1,446]`). This is a finite Monte Carlo
comparison, not equal ESS, identical trajectories or proof of posterior
equivalence. Stanli requested more leapfrogs yet completed this synthetic
case sooner. No slow counterexample was observed here; another seed would
not be justified merely to seek the preferred sign. Parallel-chain cache
competition and other machines are not measured by this serial-chain run.

Three unconstrained points from the Stanli posterior were independently
replayed through both native gradient drivers. The paired gradient S/C median
was 0.224 [0.213, 0.232]. Of 3,021 density/gradient components, 2,979 are
within 10 ULP. Worst discrepancy: 512 ULP on a small gradient,
`-0.0006597455622781023` versus `-0.0006597455622781578`, absolute
`5.55e-17`, relative `8.41e-14`. Maximum scaled error over these points is
`2.66e-15`, which does not prove a 10-ULP bound. Across the arbitrary-point
screen the largest ULP discrepancy is 4,544 on a gradient near `-0.0209`
(absolute `1.58e-14`); all pointwise values are retained. No tolerance was
widened and cancellation is not established solely from small magnitudes.

## Reproduction and retained evidence

Generator controls are environment variables: `ISSUE657_SUBJECTS`,
`ISSUE657_FAMILY=gaussian|bernoulli|poisson`, `ISSUE657_CENTERED=1` and
`ISSUE657_CENSOR=1`. The last flag requires noncentered Gaussian. For example:

```sh
ISSUE657_SUBJECTS=10,500 Rscript harnesses/issue657_mixed_model.R emit OUT/gauss_nc 5
ISSUE657_SUBJECTS=500 Rscript harnesses/issue657_mixed_model.R emit OUT/gauss_nc_n100 100
ISSUE657_SUBJECTS=10,500 ISSUE657_CENSOR=1 \
  Rscript harnesses/issue657_mixed_model.R emit OUT/cens_nc 20
```

The native driver is built against the selected runtime library and current
`runtime/include`. Its options follow the existing native timer; the
reference adds `--timed` before those options. `STANLI_BENCH_LEGACY_GRAD`
selects `stanli_grad` for older releases that predate `stanli_grad_err`; both
comparison arms must select that same call when using the legacy option.
It was **not defined** for the current measurements. Default binary SHA256
`8ddd58fd18250dcd82b7613757165c37973e20b43776a0dcdab29dd6a154d5a4`
was unchanged after adding that compatibility option and formatting.

Set `R_LIBS` to the privately installed source wrapper, `STANLI_RUNTIME` to
the exact runtime, `CMDSTAN` to the pinned checkout and `STAN_NUM_THREADS=1`.
Then, for each backend (`stanli` or `cmdstan`):

```sh
ISSUE657_CHAINS=4 Rscript harnesses/issue657_fit.R BACKEND CASE_DIR DATA.json OUT 1000 1000 657
```

The [raw lossless archive](data/issue657-native-2026-11-23/raw.json.gz)
contains exact native/reference compile argv and compiler identity, runtime
and binary hashes, generator metadata and data hashes, every gradient
repetition/pointwise result, all fit commands and phase/diagnostic results,
stdout/stderr logs and the posterior oracle points. The
[compact summary](data/issue657-native-2026-11-23/summary.json),
[saved per-draw sampler diagnostics](data/issue657-native-2026-11-23/sampler-diagnostics.rds)
and all-variable [Stanli](data/issue657-native-2026-11-23/gauss_nc-j500-n5-stanli-standard-summary.tsv)
and [CmdStan](data/issue657-native-2026-11-23/gauss_nc-j500-n5-cmdstan-standard-summary.tsv)
posterior summaries are durable Git evidence. Full raw draws/CSV remain
untouched in the issue worktree's `.cache/issue657/screen/fits/`; their exact
absolute paths, sizes and SHA256 hashes are in `retained_large_files` in the
archive. Generated source/data remain reproducible cache artifacts; no
executable prototypes live in documentation directories.

Affected diagnostic C++ targets were rebuilt from source and full compiler
output inspected: no diagnostics. The pinned clang-format 22.1.8 was used;
the R harnesses parsed and completed their recorded executions, and staged
whitespace checks passed. This changed investigation tooling and evidence,
not the production compiler pipeline; no candidate/runtime change or corpus
performance claim is presented.

The next question is which program, hardware, sampler-work or interface
difference can explain the public report. Its missing original inputs remain
one route to discrimination, but did not prevent the synthetic tests above.
The tested variants now narrow the search beyond the first proxy. Preserve
the report as unresolved and avoid a speculative optimization without an
observed generic bottleneck.
