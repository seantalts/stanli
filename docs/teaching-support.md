# Generated models and R workflows

Stanli runs Stan programs without compiling a separate C++ model. Use Stan
source and data generated by brms or Rethinking, then inspect and plot the
result with familiar R packages. For argument-by-argument migration, see
[Coming from cmdstanr](from-cmdstanr.md).

Model support is tested through the shared [corpus inventory](corpus-status.md)
and [numerical replay](../TESTING.md#comparison-with-cmdstan-on-complete-models).
These tests establish coverage for the recorded source/data combinations;
untested formulas and inputs can exercise different behavior. The
[benchmark results](benchmarks.md) report gradients, complete sampling and
preparation with each run's inputs and revision retained.

## Generated models and package backends

The Rethinking route produces a **`stanli_fit`**, not a fitted `ulam` object.
For brms there are two routes: the generation calls below, which also give a
`stanli_fit`, and a complete `brmsfit` through the backend brms provides for
its own tests, described after them.

### From brms

Use the same formula, data, family, and priors in both generation calls:

```r
library(stanli)
d <- data.frame(x = seq(-1, 1, length.out = 20),
                y = c(-1.0, -0.6, -0.8, -0.4, -0.5, -0.1, -0.3, 0.1, 0.0, 0.3,
                      0.1, 0.5, 0.4, 0.8, 0.6, 1.0, 0.9, 1.3, 1.1, 1.5))
code <- brms::make_stancode(y ~ x, data = d, family = gaussian())
data <- brms::make_standata(y ~ x, data = d, family = gaussian())
model <- stanli_model(code = code, data = data)
fit <- sample_model(model, chains = 4, seed = 1, refresh = 0)
stanli_diagnose(fit)
```

To get a complete `brmsfit`, hand the converted fit to `brm()` with its
`"mock"` backend, which checks the code and takes a finished `stanfit`. This
works with released brms (2.23) and needs rstan installed for the `stanfit`
class, but no C++ toolchain:

```r
bf <- brms::brm(y ~ x, data = d, family = gaussian(),
                backend = "mock", mock_fit = as_stanfit(fit))
summary(bf)
brms::conditional_effects(bf)
brms::loo(bf)
```

`summary()`, `posterior_predict()`, `log_lik()`, `loo()`,
`conditional_effects()` and `pp_check()` are tested on such a fit
(`r/tests/testthat/test-brms-support.R`). Methods that sample again
(`update()`, `kfold()`) do not work this way, because brms does not know how
the fit was made. A `backend = "stanli"` for brms itself, with which they do,
exists as a branch and is not part of any brms release;
[`output/brms-end-to-end`](../output/brms-end-to-end/README.md) records how it
compares with the rstan backend on the 124 brms formulas of the corpus.

Parameter names are those generated by brms. Inspect `fit$columns` when
choosing variables for plots. Pass all desired prior/family options to both
`make_*` calls rather than changing the resulting Stan text.

### From Rethinking

In the pinned rethinking 2.42 interface, `sample = FALSE` returns the prepared
model and data without fitting it:

```r
prepared <- rethinking::ulam(
  alist(y ~ dnorm(mu, sigma), mu ~ dnorm(0, 1), sigma ~ dexp(1)),
  data = list(y = c(-0.8, -0.2, 0.1, 0.4, 0.9)), sample = FALSE)
model <- stanli::stanli_model(code = prepared$model, data = prepared$data)
fit <- stanli::sample_model(model, chains = 4, seed = 1, refresh = 0)
stanli::stanli_diagnose(fit)
```

For a book model, preserve its preceding data preparation. The corpus generator
records the exact code-box sequence, package pin, and simulation seeds. Models
that the book deliberately makes difficult can also have poor diagnostics in
Stanli; changing the execution engine does not fix an unidentified model.

## Familiar R workflows

| Task | Stanli expression |
| --- | --- |
| Inspect posterior draws | `draws <- stanli::as_draws_array(fit)` |
| Get cmdstanr's default summary columns | `posterior::summarise_draws(draws)` |
| Get stansummary's table | `summary(fit)` |
| Plot traces and divergences | `bayesplot::mcmc_trace(draws, np = bayesplot::nuts_params(fit))` |
| Use tidybayes | `tidybayes::spread_draws(fit, mu)` when the model declares `mu` |
| Compare predictive accuracy | `loo::loo(fit)` when the model declares pointwise `log_lik` in generated quantities |
| Use RStan draw consumers | `sf <- stanli::as_stanfit(fit)`; then `rstan::extract(sf)` |

`as_stanfit()` constructs the fit in memory and provides native density,
gradient, and transform methods through the retained model. RStan is optional;
conversion compiles no C++ model. Read the [compatibility and persistence
limits](stanfit-compatibility.md), including the Jacobian requirement, restoring
live models after serialization, and unsupported RStan resampling operations.
For argument-by-argument translations, including initialization and optimization,
see [Coming from cmdstanr](from-cmdstanr.md).

## How to read the evidence

**Numerics:** the common corpus replay compares log density, every gradient
component and recorded constrained/generated outputs with independent CmdStan
answers at three parameter vectors. It checks exact output names and order.
The usual scaled-error gate is `1e-9`; documented ill-conditioned exceptions
and matching domain refusals remain visible in the [numerical policy](../TESTING.md).
A shared refusal is not evidence of a matching finite gradient. Fixture counts
and per-model evidence live in the [corpus status](corpus-status.md).

**Sampling quality:** examine divergences, tree-depth hits, R-hat and effective
sample sizes before using elapsed time to compare useful inference. A short
sampling smoke test checks execution and complete output, not convergence.
The common benchmark settings do not reproduce every book model's tuning choices.

**Performance:** the [common protocol](benchmark-protocol.md) separates
compilation, preparation, warm gradients and complete CLI runs. Failed or capped
seeds remain failures rather than contributing a partial average. Historical
reports retain their original protocols and revisions; later fixes do not
rewrite those measurements.
