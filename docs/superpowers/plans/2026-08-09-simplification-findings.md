## Rejected by design (per reviewer)

### compiler

- Collapse the dozen hand-written density branches (multi_normal family, lkj, lkj_cov, wishart family, multi_gp, multi_student_t, the GLMs, ordered_probit, wiener, multinomial family) into one data table like kDens, with per-entry callbacks for K/reps/variant.: Each branch encodes a distinct, individually documented shape rule (K from the matrix argument, reps from y's length, X must be a *data* matrix, per-family activity masks tied to how the kernel binds its arguments) plus a comment recording the bug that produced it. A table with callbacks would replace explicit, greppable rules with indirection and would not remove a concept; the X-macro lists already cover exactly the families that are uniform, which is the design's stated line.
- Fold `run_write_array` into `run` behind an `in_write_array` flag, since both build roots and run the pass pipeline.: The two pipelines deliberately differ: write_array runs no const_fold and no carve_islands, has no target terms or jacobian, uses a different root set, invents a dummy result slot, and catches CompileError to emit a truncated column list. Merging would put four conditionals inside one function to save two lines of root-building, and would make it easy to accidentally give the write_array graph a pass it must not have.
- Move SlotInfo (rows/cols/data_like) into graph.hpp's `Slot` to delete the `info` vector parallel to `g.slots` and its four `info.resize()` calls.: Slot is the IR and is deliberately dull; the passes create slots freely and would all become responsible for maintaining compiler-only shape state they have no way to compute. The parallel vector is the cheaper end of that trade. (The `len` duplication inside SlotInfo is a separate matter and is listed as a finding.)
- Replace `reduce_terms`' six-at-a-time ADD_N chain with a single wide reduction, or sum the target terms in a different order.: The six-input Op limit is a documented design constraint (graph.hpp, and lower.cpp refuses gaussian_dlm_obs for the same reason), and the order target terms are summed in is part of the bitwise agreement with CmdStan. tools/bench_opcost.cpp deliberately mirrors this chunking.
- Delete lower_expr's EOr/EAnd case, since its body (try_fold_const then fail) is byte-identical to the default case.: The only difference is the error text, and 'boolean operator on parameters unsupported' names the actual refusal where 'unsupported expression' does not. Fail-loudly-and-specifically is the stated contract for everything outside the supported MIR slice.
- Unify the compiler's five name maps (`scope`, `int_env`, `int_locals`, `decl_dims`, `decl_lens`) into one Scope struct so `lower_call_udf`'s save/restore is a single copy.: Considered seriously and rejected: it churns every lookup in the most delicate file in the project to save roughly eight lines, and `td.env()` -- a sixth map that is saved and restored alongside them -- belongs to the MIR interpreter and cannot join the struct, so the 'one symbol table' story would be false anyway.
- Skip the FnCheck / check_matching_dims / propto refusals and the `~`-inside-an-island rejection by approximating them.: All four are documented refusals with recorded failure modes (an lp off by log(2*pi)/2, value checks that must still reject a draw). They are the design, not incidental complexity.
