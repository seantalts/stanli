## What upstream already completed

PR392 implements mixed-cell constancy, shared frame programs with bounded
working versions, a temporary compiled recorder, and index/iterator
specialization. It supersedes our proposed first-generation shared-code and
recording-memory work. Its retained six-pair results report approximately
1.52 GB peak RSS and 499 ms warmed gradients at 4,000 rows, versus 10.43 GB
and 587 ms before numerical frames. The final recorder comparison reports
15.27 s for the first gradient. These are historical measurements, not a
fresh baseline for this task.

The old whole-stream freeze-copy proposal is not the next experiment: the
default large-model path now seals numerical frames. We must inspect the
current path and measure its remaining cost. Prior ordinary-model timing/RSS
attribution was deferred; preserve that record without treating it as evidence
of universal parity or reopening it as a prerequisite to ctsem research.

## Objective and scope

Improve ctsem evaluation cost using generic compiler/runtime properties while
preserving numerical behavior, exception order, safe fallback, and unrelated
model performance. Report source compilation, MIR preparation, first
gradient, warmed forward/reverse, changing-parameter evaluations, and memory
separately. Sampling speedups require sampling measurements.

The execution sequence below chooses a bounded implementation from new
evidence. It does not commit to simultaneously rewriting frames, autodiff,
parallel reductions, and native code generation. Successful changes must have
a reproducible evaluator and a coherent, reviewable diff. A failed hypothesis
must retain its evidence and the next decision, without becoming a default.

## Revised hypothesis ledger and execution sequence

### 1. Establish the post-392 baseline and choose the numerical target

Use an unchanged local build to attribute warmed cost to matrix kernels,
frame replay/dispatch, and memory traffic. Measure guard failures across a
deterministic sequence of parameter points; a nonzero count matters in
proportion to its time and memory cost. Inspect the final first-recording
profile only as historical evidence; its shares do not describe warm replay.

Decision artifact: a current phase table, sampled warmed profile, numerical
reference identities, and a selected bounded optimization with removable
cost and replacement cost stated separately.

Use a warmed stack sample, not the top-level opcode profiler (which sees the
retained body as OP_LOOP), together with a kernel/variant census. A provisional
10% combined solve/matrix-exp inclusive share is the kernel-track selection
threshold; below it, defer broad kernel work and follow the dominant stack.
This is a prioritization rule, not a numerical or completion allowance. Capture
respecialization counters under `STANLI_STRUCTURED_LOOP_DIAGNOSTICS`.

### 2. Remove avoidable matrix-solve tape work, then test retained factors

The active solve forward still constructs a nested Stan Math tape; backward
already uses direct formulas but rebuilds its factorization. First reproduce
the pinned active overload's numerical algorithm on doubles for eligible
families/shapes/activity combinations. The plain active left solve uses QR,
whereas the value-only path uses LU. Right and mixed overloads must be read
individually; mathematical equivalence is insufficient.

Initial eligible families: plain left (double Householder QR), SPD left/right
(double LLT with the pinned activity-specific solve expression), and triangular
left (double triangular solve). Preserve vector/matrix types and validation
order. Plain and triangular right instantiate var-scalar prim templates and
stay on the established path. Enforce bitwise forward values against the
test-side nested-tape oracle, rather than the pullback suite's default tolerance.

Prove forward parity before changing retention. Preserve the old path for
unsupported variants and all failures not covered by the proof. Retain the
old implementation as an isolated comparison during the experiment without
adding environment lookups or diagnostic branches to every unrelated call.

If factorization cost remains material, retain the necessary factor data in
the existing per-execution kernel scratch. Retained bodies reject mutable
KernelState; a per-site factor would also be overwritten by later iterations.
Prove lifetime and rebinding through frame sealing, repeated evaluation,
different inputs and executor copies. Measure added retained bytes against
removed factorization work. A factor created only during backward has no reuse
benefit unless an additional consumer is demonstrated.

Only plain-left QR and SPD LLT have factors to retain; triangular solves have
none. Use the existing scratch-size hook and frame scratch rebinding. Right
SPD needs special care: forward factors lower(A), while the current backward
factors lower(A-transpose). Accepted nearly symmetric inputs can distinguish
these, so factor reuse requires an additional proof or a safe fallback.

Decision: integrate only the independently correct, measured winning stages.
Keep direct-forward and factor-retention results separately attributable.

### 3. Counterproposal: improve the matrix exponential derivative algorithm

If the warm profile identifies matrix exponentials as the larger opportunity,
test a dedicated Fréchet derivative against the current doubled-dimension
block exponential. This changes arithmetic and needs the existing 60-digit
oracle, scale-relative accuracy tests, nonsymmetric/non-normal matrices,
runtime extents, nonfinite behavior, and full model/corpus comparisons.
First test the derivative algorithm independently of retaining forward Padé
intermediates; neither improvement presupposes the other. Numerical and memory
costs, including additional saved factors, decide whether to continue.

This is a genuinely different explanation for the remaining cost from replay
dispatch or metadata. Run a small comparative kernel experiment if the profile
supports it; otherwise record the observed reason for deferral. It must not
turn into an unrelated backend rewrite merely to provide a second candidate.

### 4. Follow the residual profile and validate the surviving implementation

After each representation/numerical change, refresh the profile. Consider
segment fusion or further recorder/frame encoding work only when the new
profile supports it. Local specialization remains conditional on measured
re-recording cost. No speedup estimate comes from storage size alone.

Subject parallelism remains separate architectural work: current reduce_sum
child lowering disables retained loops and its import proof rejects stateful
or dynamic children. Partial matrix resets and population setup also need an
independence proof, and changed reduction order needs numerical validation.
Clone reuse additionally requires a recorded source and the actual sampler
call order. Neither is a prerequisite for this numerical-kernel iteration.

Before delivery, reconcile the Fable review, update this log with commands,
decisions and results, inspect the final diff, and leave only evidence-backed
production changes with the evaluator and tests needed to reproduce them.

## Review and results

The requested review and its reconciliation are retained in

### Fresh baseline and first decision

An unchanged Release build at the base above reproduces the recorded scale:
1.423 s MIR preparation, 15.232 s first gradient and 1.531 GB peak RSS for
4,000 rows. A 10 s stack sample confined to a 15 s warm measurement window
contains 7,611 main-thread samples. Inclusive solve-forward stacks account
for 1,441 samples (18.9%), solve-backward for 1,311 (17.2%), and the matrix-exp
forward/backward kernels for 350 (4.6%). The QR-constructor subtree under
plain-left backward alone has 972 samples (12.8%). These are sampled costs,
not speedup forecasts; the profiled 521 ms gradient is not the uninstrumented
paired performance result.

The static retained-body census contains active plain-left vector solves at
orders 10 (two sites) and 55 (one site), and an active right-SPD matrix solve
at order 10 with 20 RHS rows. All use both-active variants. The dynamic
matrix-exp call is also present. Site counts do not give execution counts.

Decision: implement direct eligible solve forwards, then measure them alone.
The fresh QR evidence also supports a later, independently measured scratch
retention experiment. Defer the Fréchet alternative: all exponential kernels
together occupy much less warm time than solves, while changing the derivative
algorithm introduces a separate accuracy obligation.

Artifacts: `baseline-profile/` (command, sample, census, phase snapshots),
`baseline-identities.json`, `driver/` (shared phase-driver source/object and
link commands), and `baseline-vs-direct/` (six-pair experiment).

### Stage 2b experiment: retain the forward QR for backward

The forward saves the packed QR matrix and Householder coefficients in the
kernel's existing per-call scratch. Backward applies the corresponding
Householder sequence and triangular solve, preserving the previous expression
and accumulation order. Null-scratch callers and right solves keep recomputing.
The value-only branch still uses prim LU. No global cache, input-value hashing,
model identification or new runtime state is introduced.

The updated native pullback suite compares cached and recomputed gradients
bitwise across activity/shape combinations. `test_solve_reuse` additionally
changes the divisor on every loop iteration, compares against scratch-disabled
kernels, forces both streams and numerical frames, alternates value-only calls
with gradients, changes parameters, and checks independent executor copies.
It verifies that the requested frame mode actually executes. All tests pass.

### Ordinary controls and a bounded retention follow-up

The 322-case screen (319 historical inventory cases plus three local canaries)
has 319 finite bitwise matches and three matching nonfinite cases. Its median
warm ratio is 0.9966; individual short-window signals are noisy. Seven canaries
received six full pairs. The solve fixture improves about 16%; most unrelated
canaries are near neutral. A fixed six-pair A/A and A/B follow-up of eight
screened cases leaves positive timing signals for `ch11_m11_4`, `hmm_example`,
`logearn_height` and `s2_mm_weights` (roughly 2–6%). Do not declare universal
ordinary-model parity from the inventory median.

The retained direct-only intermediate is neutral in a further six-pair
comparison on those four cases. Their graph census contains no solve calls,
so extra QR work or scratch allocation on their executed graphs cannot
explain the signal. The saved-QR stage adds approximately 12.7 KB of text to
the matrix-kernel object and introduces new map-typed Householder template
instantiations. Link layout or shared template code generation is a hypothesis,
not yet established attribution.

Bounded counter-experiment: reconstruct the saved factor into the same MatD /
VecD HouseholderSequence types already used by the old backward, instead of
introducing map-typed sequences. This strengthens the arithmetic-type match
and removes those new template variants, at the cost of extra factor copies.
Run exact tests, measure target viability, and repeat the four affected ordinary
cases before selecting it. If it does not resolve the evidence, retain the
independently winning direct-forward stage and leave QR retention out of the
default rather than claiming unverified ordinary parity. No arbitrary binary
padding or repeated timing-until-success is part of this experiment.

The original-type variant passes the exact forward, cached/recomputed gradient,
guard re-recording, frame, changing-input, value-only and clone tests. Its text
section removes 8,592 bytes relative to the map-based prototype. Six-pair
controls against the unchanged base give ratios 0.9868 (`ch11_m11_4`), 0.9913
(`hmm_example`), 1.0023 (`logearn_height`) and 0.9994 (`s2_mm_weights`); all paired
bootstrap intervals include 1. The map-based retention prototype is rejected;
the MatD/VecD variant proceeds to final target and broad-control measurements.
This is an empirical choice between expression types, not a proven attribution
of the earlier signals to either layout or compiler heuristics alone.

Original-type candidate numerical checks again match the base bitwise at all four sizes
and three parameter points, and all 329 reference models pass. Full CTest again
passes 262/264, with only the two baseline manifest freshness failures. Actual
object members in the measured archive and the final build compare byte for
byte; the archive container hash changes on relink due to metadata.

### Final selection: direct forwards, with retention deferred

The original-type QR prototype improves full-size target medians from 497.6
to 413.3 ms (paired ratio 0.8261, interval 0.7868–0.8425), but the final broad
screen identifies additional ordinary signals. One fixed six-pair A/B and
six-pair identical-binary A/A confirmation on the four largest spikes leaves
two positive signals: `lotka_volterra` has A/B ratio 1.0725, interval
1.0420–1.0936, and A/A-adjusted interval 1.0008–1.0824; `s2_mv_subset` has
ratio 1.0219, interval 1.0011–1.0525, and adjusted interval 1.0076–1.0670.
The other two intervals include parity. Do not hide these signals behind
the inventory's near-neutral aggregate or the successful earlier controls.

The saved direct-only intermediate is neutral on both affected cases in
six-pair comparisons (ratios 0.9924 and 0.9927). Accordingly, exclude the
original-type QR variant as well. Restore the independently measured direct
stage, retain the exact forward oracle and legacy-activity coverage, and
archive the retention implementation plus its lifetime fixture in
`.cache/ctsem-post-392/reuse-matrix/`. No QR hook, retained-factor state or
retention-specific test remains in the production diff. The final runtime
archive's actual object members match the original direct-only archive
byte for byte, so that stage's measured results remain applicable.

The selected full-size improvement is 501.4 to 473.6 ms, with paired ratio
0.9456 and interval 0.9397–0.9558, and no added retained storage. The larger
retention opportunity remains plausible but unintegrated. Its next experiment
must explain or eliminate the ordinary-model cost, for example by separating
shared-template code generation from solve-local work. A repeated timing
round or arbitrary binary padding would not resolve that architectural
question. The final scorecard and phase/control results are in
`notes/performance/2026-09-20-ctsem-solve-kernels.md` and its JSON companion.

Final selected-build gates: 261/263 CTest tests pass, with only the two
baseline manifest failures; 329/329 reference models at three points pass
all 1,020,194 values. The 322-case ordinary screen has 319 finite bitwise
matches and the same three nonfinite points in both builds. Its geometric
mean ratio is 1.00122; short single-pair outliers are not parity evidence.
Seven six-pair canaries show the expected solve gain. The mixed-cell canary's
small positive timing signal receives one fixed A/B and A/A follow-up:
ratio 1.0080, interval 0.9876–1.0235, and adjusted interval 0.9776–1.0350.
It is inconclusive. The six cases implicated by the QR prototypes are all
neutral under direct-only six-pair controls.

The selected phase diagnostic gives forward 246.8/220.9 ms and reverse
251.2/253.1 ms over 20 warmed evaluations. The refreshed warm profile assigns
15.1% to solve forwards, 18.2% to solve backward and 4.4% to exponentials.
Changing points 0→1→2→0 with interleaved value-only calls remain bitwise at
all four sizes, with no target re-recording. Frame program/cell/binding counts
match the base. This completes the bounded iteration; the retained-factor
beam is deferred on performance evidence, and its patch is preserved at
`notes/performance/2026-09-20-ctsem-qr-retention.patch` with a passing
