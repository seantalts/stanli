# Perf Phase 2 Plan

**Goal:** Remove the remaining classes of scalar/quadratic work the corpus
census exposes, in measured-impact order, and enable packet (varmat-style)
kernel math where stan-math has a varmat overload.

## What the census says (2026-08-06, `spikes/op_census.py`)

120 models lower to 3,008,913 ops, of which **2,417,317 (80%) still have a
scalar output**. Top opcodes by scalar-output count, corpus wide:

| opcode | scalar ops | models |
| --- | ---: | ---: |
| INDEX | 1,052,997 | 80 |
| ADD | 464,072 | 35 |
| LOGV | 359,474 | 14 |
| MUL | 222,864 | 37 |
| NORMAL_LPDF | 163,131 | 84 |
| LOG_SUM_EXP | 40,636 | 9 |

The worst models are the hierarchical family (`radon_*` x12,
`election88_full`, `radon_hierarchical_*`), all sharing one idiom:

```stan
for (n in 1 : N) {
  mu[n] = alpha[county_idx[n]] + beta * floor_measure[n];
  target += normal_lpdf(log_radon[n] | mu[n], sigma_y);
}
```

Measured on `radon_county_intercept` (N=12,573, J=386, 388 params):

| | stanli | CmdStan |
| --- | ---: | ---: |
| ns/gradient | 90,515,108 | 438,082 |
| ratio | **207x slower** | 1x |
| peak RSS | 2.58 GB | — |

## Cause: the functional-update chain is quadratic

`mu[n] = ...` under an unrolled loop lowers to a *functional update*
(`lower.cpp`, "Element write under unrolled control flow"): each write
emits `OP_SET_INDEX`, whose kernel is

```cpp
for (i < out.len) out.data[i] = in[0].data[i];   // copy the WHOLE vector
out.data[idata[0]] = in[1].data[0];              // then poke one element
```

and whose output is a **fresh slot of the full vector length**. N writes
therefore cost O(N^2) time and O(N^2) arena: 12,573 slots x 12,573
doubles x 8 bytes x 2 arenas = 2.5 GB, matching the measured RSS.

This is a scalability bug, not interpreter overhead. It dominates
everything else in the census (the 1.05M scalar INDEX ops are mostly the
read-backs riding along with these chains).

## Priority order (measured, not assumed)

1. **In-place functional updates.** O(N^2) -> O(N) time and memory.
   Unlocks the whole hierarchical family. Biggest measured win available.
2. **GATHER re-roll.** `alpha[idx[n]]` with an arbitrary data index is
   the one input class the re-roll pass cannot classify today; with (1)
   done, adding it vectorizes these models outright rather than merely
   making their scalar chain cheap.
3. **Batched LOG_SUM_EXP / elementwise-lp density.** `low_dim_gauss_mix`
   (0.53x), `hmm_gaussian`, `normal_mixture_k`: 40,636 scalar
   LOG_SUM_EXP ops across 9 models. Previously believed to be the top
   item; the census demotes it.
4. **Packet (varmat) kernel math.** Requested; orthogonal to 1-3 (it
   speeds up work that is already vectorized). Gated on its own
   measurement, see below.

## Item 1: in-place functional updates

**Safety condition (last-use, not single-use).** Rewriting
`out = SET_INDEX(in0, v, k)` into a destructive `in0[k] = v` is sound iff:

- `in0` is produced by an op (NOT a fill-backed data/const slot: fills are
  applied once at bind time, so mutating one would leak state across
  gradient evaluations — the first write in each chain therefore keeps its
  copy, which is the single O(N) copy per evaluation),
- this op is the **last** use of `in0` in program order (later reads of
  `in0` would otherwise observe the mutation — note the read-back
  `INDEX(mu_n, n)` in the same lane is an *earlier* use, so it is fine),
- `in0` is not a parameter slot and neither `in0` nor `out` is a root.

**Reverse mode.** With `out` and `in0` the same slot, their adjoint
buffers are the same too, so the non-aliased rule (`in0.adj += out.adj`
elementwise except k; `v.adj += out.adj[k]`) becomes:

```
v.adj += adj[k];
adj[k] = 0;        // in0[k] was overwritten: it does not inherit out's adj
```

**Implementation.** New opcode `OP_SET_INDEX_INPLACE` whose op has
`out == in[0]` (same slot id, so `bind_()` gives one offset with no
executor change); a pass `make_inplace_updates(Graph&, roots)` doing the
last-use analysis and renaming downstream references from the dead output
slot to `in0`.

**Expected:** `radon_county_intercept` 90.5 ms -> low single-digit ms,
2.58 GB -> a few MB. Verify: full corpus A/B (gradients unchanged), plus
peak-RSS and ns/grad on the radon family.

## Item 4: packet kernel math (varmat), and what it costs

stanli's kernels do not use `var` at all — they compute values and
partials on doubles. "Enabling varmat" therefore means mirroring the
*varmat expressions* (contiguous, packetizable) instead of the AoS ones.
Today the kernels deliberately do the opposite: `constrain.cpp` documents
that CmdStan's `Matrix<var>` rev overloads evaluate transcendentals over
strided `.val()` expressions Eigen cannot packetize, so our kernels use
**scalar libm per element and sequential reductions** to stay bitwise
with default CmdStan.

So this item is a deliberate trade, and it must be stated before it is
made: packet math would move the 44 currently-bitwise models to ~1-2 ULP,
i.e. stanli would be bitwise against `stanc --O1` CmdStan builds rather
than against default CmdStan. That is inside the project's 2-ULP budget,
but it changes which configuration is the reference.

**Gate:** microbenchmark scalar-libm vs packet Eigen for the ops that
actually appear at scale (exp, log, inv_logit, sequential vs vectorized
sum) at realistic N, before touching any kernel. Convert only where the
measurement justifies it, function by function, and verify differentially
against `stanc --O1` CmdStan.
